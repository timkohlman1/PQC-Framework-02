IMPLEMENTATION REQUEST 2 — Align Ready Metrics 2 timing names and origins

Review and update Ready Metrics 2 so every application-visible timing metric has one unambiguous origin and the firmware/result schema uses the same terminology as the thesis.

Use the following canonical definitions:
- RTFB: reset origin to first byte of the requested application payload.
- RTLB: reset origin to final byte of the requested application payload.
- TTFB: TCP connection initiation to first byte of the requested application payload.
- TTLB: TCP connection initiation to final byte of the requested application payload.
- ReqTFB: application transfer request to first byte of the requested application payload.
- ReqTLB: application transfer request to final byte of the requested application payload.

TTFB/TTLB must remain connection-relative so they are comparable with the TLS/Web literature used by the thesis. In particular, the TTFB interval includes TCP establishment, TLS, MQTT connection, the application request and the first application response byte; TTLB uses the same TCP-connect origin and ends at the final byte of the complete requested payload.

Do not label the first MQTT CONNACK/plaintext response byte as TTFB. Retain it as a separate MQTT-readiness/first-response checkpoint. If the existing `ttfb_ms` field currently refers to the CONNACK response while `application_ttfb_ms` refers to the first application-payload byte, migrate the canonical names so `ttfb_ms` represents the application-payload definition above and the MQTT checkpoint receives a distinct field name. Preserve backwards-compatibility only where it cannot create ambiguity in new result records.

The intended end state must provide a reset-relative origin rather than reusing the current post-HAL application checkpoint. Establish the reset origin at the earliest framework-controlled wolfBoot entry after hardware reset and before firmware verification, retain the clock/timing provenance needed to interpret that marker, and propagate the reset-relative state through the existing bootloader-to-application handoff/mailbox. The result schema must identify this operational reset origin explicitly so RTFB/RTLB are not confused with an external oscilloscope measurement of the NRST electrical edge.

Record the six derived metrics together with the underlying checkpoints (reset origin, TCP-connect start, MQTT readiness, application request, first application byte, final application byte). Retain payload-transfer duration from first to final byte as a separate optional metric; it is not ReqTLB.

Keep measurement overhead outside the critical intervals as far as practical. Update structured MQTT/UART evidence, result schemas, host parsers, validation rules, tests, workload documentation and Chapter 4 source comments so old and new metric names cannot be confused.
